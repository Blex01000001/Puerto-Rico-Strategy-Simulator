# ml/（學習型局面價值函數：訓練端）

Python 子專案：產生資料用 Runner（C#），訓練在這裡，推論在 Engine（C#）。讀到這個資料夾的檔案時自動載入；全專案規則在根目錄 `CLAUDE.md`，流程與指令在 `ml/README.md`。

## 檔案地圖
- `positions.py`：讀 Runner 的 dump（`.bin`＋`.bin.json`）；`expand`（萬用字元／資料夾展開）、`read_meta`（格式、版本檢查）、`load`（多檔需同特徵清單、`featureVersion`、人數）、`split`（依局切驗證集）。
- `modelmeta.py`：`<模型>.meta.json`（參數、資料來源、驗證成績、特徵重要度、環境、`matches` 對戰勝率）；`write`／`read`／`match_entry`（含耗時 `seconds`、`engineVersion`、`engineCommit`，舊紀錄缺的從結果檔補）／`add_match`／`match_summary`／`dump_summary`／`train_summary`（對戰紀錄、資料產生、模型訓練轉成貼給 AI 的短 Markdown；ML UI「複製摘要給 AI」用，只有複製鈕不顯示文字（`copy_button`：小 iframe 裡的按鈕，`navigator.clipboard`，被擋時退回 `execCommand`）：模型清單的對戰紀錄與排程佇列的「工作詳細」（`job_summary_text`）；`match_summary` 欄位要與 `match_entry` 同步）／`move_model`／`rename_dump`＋`dump_references`（訓練資料改名）／`model_digest`＋`dump_digest`＋`digest`（管理頁「複製給 AI」的精簡文字，`DIGEST_LIMIT` 字數上限）。正式模型（`ml/models/`，git 追蹤）的對戰紀錄寫在 `ml/local/match-records/<模型>.matches.json`，`read` 時合併（標 `local: true`），追蹤中的 `.meta.json` 不會被改；本機模型直接寫進自己的 `.meta.json`。
- `fingerprint.py`：**配方 hash**。同一組參數（配方）一定得到同樣的檔案（引擎對設定與種子是確定的），所以配方的 SHA-256 能回答「這兩份是不是一樣」，配方本身能回答「差在哪」（`describe`：局數 20,000 → 200,000、座位 2 的策略版本 build-first：v1 → v2…）。配方內容（`HASH_FORMAT` 2）：資料＝規則集（`base`）與規則版本、預留的 `variant`／`variantOptions`（目前空）、人數、已打局數、種子、抽樣率、座位順序（小寫）、每個座位的策略、**策略版本**（`revisions`，MCTS 含 rollout 策略）與**完整參數**（預設值已填；`valueModel` 換成**檔案內容** hash；依座位順序）、`limits`、`options`、dump 格式版本、特徵版本；模型＝種類、特徵版本、各份資料的 hash、訓練參數（白名單 `LGBM_OPTIONS`／`MLP_OPTIONS`；`threads` 不算，MLP 的 backend／device 用解析後的值）；對戰＝同資料但沒有抽樣率與特徵版本。**不算**：檔名、設定檔名稱、座位 id、執行緒數、引擎版本與 git commit、套件版本（只記錄與顯示）。完整參數：有 `resolvedSeats` 的檔案（引擎 0.3.0 起）直接用；沒有的舊檔用**凍結**的 `ml/strategy-params.legacy.json` 補算（`resolve_seat(..., legacy=True)`，永遠不要重產生）；還沒執行的（UI 預測）用 `ml/strategy-params.json`（引擎產生、C# 測試保證與程式一致）。`resolve_seat` 要與 C# 的 `StrategyRegistry.Resolve` 一致（MCTS 有模型、4 人局、沒寫 `leafRollout` 時補 `DEFAULT_LEAF_ROLLOUT`＝40，沒有 `resolvedSeats` 的舊檔（legacy）仍是 0；rule-based＝它的 profile 加 `profile` 參數、MCTS 加 rollout 策略的版本；`tests/test_runner_jobs.py` 用真的 Runner 比對預測與實際的 hash）。`stale_notes` 列出比目前程式舊的規則與策略版本（UI 的「版本狀態」）。ML UI 一律說「hash」，不說「指紋」。規則版本顯示成 `base-vN`（`rules_name`），策略版本 `harbor-rush-vN`（`strategy_name`）；`load_versions` 讀 `docs/versions.json`（`strategies=True` 取策略版本）。**改配方內容（遞增 `HASH_FORMAT`，先問使用者）、新增參數時要同步「hash 說明」頁（`hash_page`，參數清單大多從 `fingerprint` 的常數產生）與版本清單；版本號的規則在根目錄 `CLAUDE.md`「版本與 hash」。**舊檔缺的欄位用預設值補（`rulesRevision` 1、`rulesVersion` base、`limits` 150／20000、`autoAdvanceForced` true）；舊模型沒有 hash（標「舊紀錄」）。`current_rules_revision`／`current_feature_version`／`current_format_version`／`current_engine_version` 與 `DEFAULT_LEAF_ROLLOUT` 讀 `ml/engine-info.json`（`engine_info()`；引擎產生、C# 測試保證與程式一致；不要再用正規表示式讀 C# 原始碼），`current_strategy_revision` 讀 `ml/strategy-params.json`。
- `i18n.py`＋根目錄 `i18n/ml.<語言>.json`：UI 文字查表（鍵→字串，`{名稱}` 是參數；預設英文，也是缺字時的後備；語言順序：側欄切換鈕→網址 `?lang=`→`PR_LANG`→英文）；UI 用 `mlui/text.py` 的 `t(鍵, **參數)`。兩個語言的鍵與占位符要一樣、英文不能有中文、每頁英文模式沒有中文（`tests/test_i18n.py`）。測試預設 `PR_LANG=zh-TW`（`conftest.py`）。不用 Streamlit 的模組（`fingerprint`、`folders`）收 `lang` 參數、用 `i18n.translate`。鍵的命名與各頁的做法見 `ml/docs/ui-notes.md`。
- `llm.py`：「AI 分析」頁的 LLM 聊天（無 Streamlit，可用假的 opener 測試）：供應商清單 `PROVIDERS`（Gemini、Claude，各一個轉接器）、金鑰只讀環境變數（`GEMINI_API_KEY`、`ANTHROPIC_API_KEY`）或 `ml/local/llm.json`（頁面不輸入也不顯示；不要放 `appsettings.json`；錯誤訊息一律 `redact`）。頁面細節見 `ml/docs/ui-notes.md`；測試 `tests/test_llm.py`；待辦見 `docs/TODO.md` 11。
- `folders.py`：`open_folder(path, root)`，在這台電腦的檔案管理員開啟專案內的資料夾（Windows `os.startfile`、macOS `open`、Linux `xdg-open`；專案外、不存在、沒有檔案管理員時回傳原因）；ML UI 的 `folder_line` 用它（測試 `tests/test_folders.py`）。
- `model_report.py`：所有模型（正式＋本機）的勝率摘要表，給 `docs/models.md` 用（數字一律從這裡取）。
- `train_lgbm.py`、`train_mlp.py`：`train(data, out, progress=None, log=print, **options)` 可匯入（ML UI 用），命令列只是包一層；都寫 `<模型>`、`.meta.json`、`.check.txt`。
- `train_options.py`：兩種模型的預設訓練參數（`LGBM_DEFAULTS`／`MLP_DEFAULTS`，訓練腳本的 `DEFAULTS` 就是它們）與 MLP 後端選擇（`resolve_backend`、`torch_available`），不 import LightGBM／NumPy／PyTorch，ML UI 只 import 它。**新增訓練參數加在這裡**。
- `ui.py`＋`mlui/`：ML UI（Streamlit，`streamlit run ml/ui.py`）。`ui.py` 只是進入點（缺套件檢查、左側導覽 `pages()`、`main()`）；每頁一個模組 `mlui/<頁>.py`（`data` 模擬對局採樣、`train` 模型訓練/蒸餾、`match` 對戰驗證、`pipeline` 建立排程（導覽第一頁、預設頁）＋`plan`（項目的計畫：不畫元件，測試直接呼叫，`tests/test_plan.py`）、`datamanage` 訓練資料、`models` 估值模型、`analysis` AI 分析、`jobqueue` 排程佇列、`helppages` hash 說明與版本控管；`data`／`train`／`match` 在導覽的「單項工作（舊版）」分組）；其他頁要把一個項目交給排程頁用 `common.open_in_pipeline`（細節見 ui-notes）；兩頁以上用到的放 `mlui/common.py`，CSS 在 `mlui/style.py`，`lang()`／`t()` 在 `mlui/text.py`。**Streamlit 每次互動重跑 `ui.py`，但 `mlui` 模組只 import 一次：模組層不能算翻譯文字或讀環境變數**（要放進函式裡，例如 `kind_text()`、`match_columns()`、`pages()`；`st.dialog` 的標題在呼叫時才給：`st.dialog(t(...))(_body)(...)`）。模組可以不經 Streamlit 直接 import（`tests/test_ui.py::test_parse_params`）。版面、元件、各頁做法與踩過的雷：**`ml/docs/ui-notes.md`**（改畫面前用 grep 找相關段落）。
- 工作種類（`job_runner.py`）：`train_lgbm`／`train_mlp`（取消＝結束程序）、`dump`、`match`（呼叫發佈版 Runner `dotnet publish/runner/Runner.dll`，`PR_RUNNER_DIR` 可改；原始碼較新會先自動發佈；從輸出解析 `n/total games` 當進度；取消送 SIGINT，Windows 直接結束；`match` 完成後 `modelmeta.add_match`）。UI 寫的東西一律進本機工作區 `ml/local/`（被 git 忽略）：訓練的模型 `ml/local/models/`、自訂組合與自我對戰設定 `ml/local/data-configs/`、對戰設定 `ml/local/matches/`、排程範本 `ml/local/pipelines/`；模型名稱在正式與本機之間不能重複。重新命名、設為正式／移到本機的規則見 `ml/docs/ui-notes.md`。策略清單、座位順序、MCTS 參數順序讀 `ml/engine-info.json`（`fingerprint.engine_info()`），新增策略不用改 UI。
- `jobs.py`：背景工作（`results/ml/jobs/<id>/`：`job.json` 狀態與心跳、`events.jsonl` 進度、`log.txt`、`cancel` 旗標檔）；`start`（沒有工作在跑就馬上開始，否則狀態 `waiting` 排隊）／`start_next`（啟動最早排隊的那個；有工作在跑就不動）／`cancel`（排隊中的直接標成取消，執行中的放 `cancel` 旗標）／`list_jobs`／`active_job`／`waiting_jobs`／`queue_position`／`events`／`wait`。**管線**：`start_pipeline(name, steps)` 一次寫好整串工作（`job.json` 的 `pipeline`＝`{id, name, stage, index, total}`，建立時間嚴格遞增所以照順序跑，全部寫好才呼叫 `start_next`）；管線裡任何工作失敗、被取消或中斷（`PIPELINE_BREAKING`），同一條管線還沒開始的工作全部取消（`_stop_broken_pipelines`，在 `start_next` 與等待中工作被取消時執行，所以關掉 UI 也有效；結果記 `stoppedBy`／`stoppedByState`，已寫好的檔案保留）；`cancel_pipeline(id)` 取消整條（等待中的馬上、執行中的放旗標）；`pipeline_jobs(id)` 依順序列出。沒有明確的相依欄位：先後靠佇列先進先出，失敗靠「整條停止」。一次只跑一個；每個工作結束（完成、失敗、取消）時 `job_runner` 呼叫 `start_next`，所以關掉 UI 佇列也會繼續；程序被硬殺而沒交棒時，UI 的 `watch_states` 會補叫 `start_next`。`.dispatch.lock`（排他建立的鎖檔，超過 60 秒視為殘留）保證不會同時啟動兩個。狀態：`waiting` 排隊中、`queued` 啟動中、`running`、`done`、`failed`、`cancelled`、`lost`（心跳過期但程序還在：佇列暫停等它，`cancel` 會強制結束它與 Runner 再派下一個）、`interrupted`（心跳過期且程序已不在）。佔住佇列的狀態集中在 `jobs.BUSY`，判斷「有沒有工作在跑」一律用它。程序存活用 `process_alive`（`job.json` 的 `pid`＋`startedEpoch`：還要是 Python／job_runner、建立時間不晚於工作開始，避免 pid 被別的程式重用時誤判；Windows 用 kernel32，Linux 讀 `/proc`，殭屍程序算已結束）。`job_runner.py`：在獨立程序執行一個工作（POSIX `start_new_session`、Windows `CREATE_NEW_PROCESS_GROUP|DETACHED_PROCESS`），心跳執行緒看到 `cancel` 就結束程序。
- `data-configs/`：內建的產生資料設定檔（手寫混桌、隨機、`4p-selfplay-*`＝MCTS＋模型自我對戰）。
- `local/`（不進 git）：本機工作區，見上；在雲端 session 裡看不到使用者電腦上的這個資料夾。
- `models/`：正式模型＋`.meta.json`＋`.check.txt`（進 git）；總表與狀態在 `docs/models.md`。早期模型的 `.meta.json` 是補寫的（`params.note`、`training.note` 會註明）。
- `tests/`：pytest（`conftest.py` 產生假 dump）：`python3 -m pytest ml/tests`。`test_runner_jobs.py` 需要 .NET SDK（沒有就略過），會把 Runner 發佈到暫存資料夾。
- `requirements.txt`：`python -m pip install -r ml/requirements.txt`。
- `check_env.py`：這個 Python 有沒有 ML UI 的套件；沒有就印出該 Python 的完整路徑與 `"<python>" -m pip install -r …`（退出碼 1）。`start-ui.cmd`／`.sh`、`ui.py`（缺套件時只顯示修正指令）、Dashboard 的啟動按鈕都用它；必要套件清單在 `REQUIRED`（加套件時同步 `requirements.txt`）。
- `make_test_fixture.py`：重產 C# 測試用的小模型 `Tests/Data/tiny-lgbm.*`（改特徵後要跑）。

## 常見修改
- **換特徵**：不要改舊版。在 Engine 新增特徵集（`FeaturesV{N}.cs`，登錄進 `FeatureSets.All`，`LatestVersion` 加 1）→ 用 `Runner --dump-positions … --feature-version N`（ML UI「模擬對局採樣」的「特徵版本」，預設最新版）重新產生資料 → 重訓。舊版的模型與資料照常可用（`positions.load` 一次只能讀同一版的資料）。`Tests/Data/tiny-lgbm.*` 是版本 1 的固定樣本，不用重產。
- **改 dump 格式**：C# 遞增 `PositionDump.FormatVersion`，同步 `positions.FORMAT_VERSION` 與 `record_dtype`，兩邊測試一起跑。
- **加訓練參數**：加進 `train_options.py` 的 `LGBM_DEFAULTS`／`MLP_DEFAULTS`、`train()` 的 `params`（會寫進 `.meta.json`）與 argparse；**同步 `fingerprint.LGBM_OPTIONS`／`MLP_OPTIONS`**（影響模型的放白名單，不影響的放 `IGNORED_OPTIONS`；`tests/test_fingerprint.py` 會在漏掉時失敗）；測試在 `tests/test_train.py`；UI：補 `i18n/ml.*.json` 的 `param.<名稱>`、`pdoc.*` 與 `ui.py` 的 `PARAM_DEFAULTS`／`PARAM_DOC_ROWS`（`tests/test_i18n.py` 會檢查每個預設參數都有 `param.*`）。
- **改 hash 的內容**（新增或移除進配方的欄位）：所有舊 hash 會變成「不同」，改前先問使用者；舊檔缺的欄位要有預設值（見 `DEFAULT_LIMITS`）。
- **新模型種類**：Engine 要先能推論（`ValueModel.cs` 加類別＋與 Python 一致的測試），再寫訓練腳本；輸出格式不變的改寫（例如 MLP 改 PyTorch）只要 `.check.txt` 與 C# 比對一致。
- **管線頁加欄位**、其他頁面的做法：見 `ml/docs/ui-notes.md`「常見修改」。
- **ML UI 加頁面或工作種類**：工作種類加進 `jobs.KINDS` 與 `job_runner.run`（產生資料、對戰要呼叫發佈版 Runner：`publish/runner/Runner`，進度從 Runner 輸出解析）；頁面＝新模組 `mlui/<頁>.py`（只 import `mlui.common`／`mlui.text`，不 import 別的頁面模組；別頁也要用的函式搬進 `common.py`），在 `ui.py` import 它並加進 `pages()`（id、名稱、圖示、函式、分組標題），並在 `i18n/ml.en.json`／`ml.zh-TW.json` 補 `page.<id>`（導覽名稱與頁面標題；兩個語言的鍵要一樣，`tests/test_i18n.py` 會檢查）；需要即時更新的區塊用 `@st.fragment(run_every=...)`，工作狀態改變時整頁 `st.rerun(scope="app")`（`watch_states` 的做法）。測試：`tests/test_jobs.py`（真的開程序）、`tests/test_ui.py`（`AppTest` 無頭執行；一次只畫一頁，用 `goto(at, "<id>")` 點導覽）；畫面用 Playwright 截圖確認（Streamlit 的表格是 canvas，勾選列要點座標）。
- **新增或刪除正式模型**：三個檔一起動（`modelmeta.move_model` 或 git），用 `python3 ml/model_report.py` 取數字更新 `docs/models.md`（刪除的保留一列、狀態改「已刪除」）。
- **對戰結果記到模型**：`modelmeta.add_match(<模型>, <Runner 結果檔>)`（同一結果檔重覆加只會取代）。

## 雷
- 訓練資料很大（約 870 bytes／列）：LightGBM 會轉成 float32（257 萬列約 4.4 GB），MLP 保持 int16 逐批標準化；不要在 MLP 先整份轉 float（第一次就因記憶體不足被系統停掉）。
- 驗證集 MSE／R² 和勝率對不上（資料分布換了 R² 就會變），判斷模型只看對戰勝率（`matches`）。
- 長時間產生資料用發佈版 Runner（`./publish/runner/Runner`），見 `ml/README.md`。
- ML UI 的畫面（Streamlit 版面、CSS、按鈕與操作列、快篩、表格、彈出卡、管理頁、排程頁）有很多踩過的雷，都在 **`ml/docs/ui-notes.md`**「雷」：改畫面前先 grep 那份。
- 用 UI 測試資料／對戰時若有別的 Runner 背景工作正在用 `publish/runner`，啟動 UI 前設 `PR_RUNNER_DIR=<暫存資料夾>`：自動重新發佈會覆寫執行中的 dll。測完刪掉 UI 寫進 `ml/local/` 的測試檔（設定、模型、`match-records/`）。
- 背景工作的程序不跟著 UI 結束：測試或手動實驗後記得看 `results/ml/jobs/` 有沒有還在跑的；測試用的模型在 `ml/local/models/`（不會進 git，但記得清掉）。
- 編碼：Windows（繁中）預設輸出編碼是 cp950，`job_runner` 一律把 stdout／stderr 改成 UTF-8（`utf8_output`，`errors=replace`），`jobs._spawn` 也設 `PYTHONIOENCODING=utf-8`；Runner 在輸出被導向時改用 UTF-8（`Console.IsOutputRedirected`），讀 Runner 輸出時 UTF-8 解不開就用系統編碼（`decode`）。曾因「±」讓對戰工作在寫紀錄時當掉。
- Windows 上檔案被別的程序開著時 `os.replace` 會 PermissionError（UI 每 2 秒讀 `job.json`、防毒、索引都會）：`jobs._write_json` 會重試，`read_job` 也把它當暫時錯誤；心跳執行緒（`job_runner.heartbeat`）寫失敗只印訊息、不能讓執行緒結束。曾因此在約 10 分鐘後把還在跑的 dump 顯示成「中斷」。新的背景寫檔都走 `_write_json`。
- Windows 常有兩個 Python（Anaconda 與 python.org）：`pip` 裝到 A、`py`／`python` 跑的是 B，ML UI 就會 `No module named 'lightgbm'`。所以指示一律寫 `python -m pip`，啟動檔挑「第一個套件齊全的 Python」（`PR_PYTHON` 可指定），失敗時印出該 Python 的完整路徑與修正指令。
- Windows 的 cmd 會把 Streamlit 輸出的顏色碼顯示成 `[0m`：click 8.2 起沒有 colorama 就不轉換，所以 `requirements.txt` 在 Windows 加 `colorama`（已經裝好環境的人要另外 `python -m pip install colorama`）。
- 這個雲端環境擋住 PyTorch 的 CPU 版下載站；PyPI 的 `torch` 一定要帶 CUDA 函式庫（不帶就 import 失敗），完整安裝約 8 GB。使用者電腦裝 CPU 版即可。
- `train_mlp.py` 兩個後端（`fit_torch`／`fit_numpy`）要維持同樣的訓練規則（He 初始化、Adam＋L2、每 4 epoch 學習率減半、提早停止取最好的一輪）；匯出一律走同一段 JSON，`tests/test_train.py` 兩個後端都測（沒有 torch 就略過）並用 NumPy 從 JSON 重算 check 列。
