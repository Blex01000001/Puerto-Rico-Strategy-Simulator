# ML UI：細節與雷（ml/docs/ui-notes.md）

從 `ml/CLAUDE.md` 移出來的 ML UI 細節（版面、元件、各頁的做法與踩過的雷）。只在改 ML UI 的畫面時讀；用 `grep -n` 找要的關鍵字（函式名、元件 key、頁面 id），不用整份讀。

**函式在哪個檔**：`ml/ui.py` 只是進入點（語言檢查、導覽、`main()`）；每頁一個模組 `ml/mlui/<頁>.py`（`data`、`train`、`match`、`pipeline`＋`plan`、`datamanage`、`models`、`analysis`、`jobqueue`、`helppages`），兩頁以上共用的在 `mlui/common.py`，CSS 在 `mlui/style.py`（下文的 `CSS` 指它），`lang()`／`t()` 在 `mlui/text.py`。下文寫「`ui.py` 的 X」時，用 `grep -n 'def X' ml/mlui/*.py` 找。

## 模組與頁面（原檔案地圖的完整說明）

- `i18n.py`＋根目錄 `i18n/ml.<語言>.json`：UI 文字查表（鍵→字串，`{名稱}` 是參數）。預設英文，也是缺字時的後備；語言順序：側欄切換鈕（session）→ 網址 `?lang=` → 環境變數 `PR_LANG` → 英文；`ui.py` 的 `t(鍵, **參數)`。已查表：外殼（導覽、側欄、頁面標題與流程說明、缺套件訊息）、「排程佇列」頁與工作詳細、「對戰驗證」頁、「訓練資料」頁、「模型」頁、「模擬對局採樣」頁、「模型訓練/蒸餾」頁、「hash 說明」頁、「版本控管」頁的標籤（`docs/versions.json` 的標題、說明與修改內容是專案資料，維持中文）；ML UI 的頁面都已查表（`tests/test_i18n.py::test_every_page_is_english_and_switches_back` 逐頁檢查）；工作標題：`jobs.start(kind, title, spec, title_key, title_args)` 把 i18n 鍵與參數一起寫進 `job.json`（`titleKey`／`titleArgs`），UI 一律用 `job_title(job)` 顯示（沒有鍵的舊工作顯示當時存的文字）；`start_job(kind, title, spec, title_key, **args)` 包了它；資料列的內部欄位名稱還是中文（`來源`、`人數`…），只在 `table_view` 用 `DUMP_COLUMNS` 換成翻譯後的欄名顯示；`fingerprint.describe`／`stale_notes` 有 `lang` 參數（預設 `zh-TW`，UI 傳 `lang()`），文字在 `fp.*` 鍵；`folders.open_folder` 回傳的失敗原因還是中文。鍵的命名：`page.*`、`side.*`、`job.*`、`progress.*`、`queue.*`、`detail.*`、`remark.*`、`ver.*`、`match.*`、`mt.*`（對戰表欄位）、`mlist.*`、`common.*`（`sep`／`list` 是分隔符號）、`md.*`（模型詳細）、`dt.*`／`dump.*`／`cfg.*`／`custom.*`／`del.*`（資料頁）、`strategy.*`（策略說明）、`tr.*`／`param.*`／`pdoc.*`（訓練頁與參數說明表；加訓練參數時補 `param.<名稱>`、`PARAM_DEFAULTS` 與 `pdoc.<區>.<列>.<欄>`，`PARAM_DOC_ROWS` 的列數要跟著改）、`hp.*`（hash 說明頁；表格列用 `hash_rows`，`HASH_ROWS` 記每張表的列數）、`fp.*`（`fingerprint.py`）。表格欄位名稱是翻譯後的字串，程式裡一律用 `t(...)` 取欄名，不要寫死中文。`place_of` 回傳 `official`／`local`（不是翻譯字串）。UI 裡的區域變數不要叫 `t`（會蓋掉翻譯函式）。每翻完一頁，在 `tests/test_i18n.py` 加「英文模式下該頁沒有中文」的測試（`_texts`；CSS 的 `<style>` 區塊與專案資料除外）（英文化進行中，見 `docs/TODO.md` 8(b)）；改一段就把它搬進兩個 JSON。測試預設 `PR_LANG=zh-TW`（`conftest.py`），因為既有測試用中文標籤找元件。
- `llm.py`：「AI 分析」頁的 LLM 聊天（無 Streamlit，可用假的 opener 測試）。**供應商清單 `PROVIDERS`**（Gemini：`generateContent`、`x-goog-api-key`；Claude：Messages API、`x-api-key`＋`anthropic-version`、`max_tokens`、系統指示在最上層 `system`、角色 `model`→`assistant`；Claude 預設不啟用，因為要付費）各一個轉接器，`chat(ps, system, history)`／`list_models(ps)`／`build_body`／`model_url` 依 `ps["kind"]` 分派，`ps`＝`provider_settings(settings, 名稱)`。金鑰：`api_key(ps)` **頁面不輸入也不顯示，只顯示「有沒有讀到」與來源**——先讀該家的環境變數（`GEMINI_API_KEY`、`ANTHROPIC_API_KEY`），再讀 `ml/local/llm.json` 裡該家的 `apiKey`（使用者手動編輯）；不要放 `appsettings.json`（它進 git）；金鑰只進請求標頭，錯誤訊息一律 `redact`。設定檔 `load_settings`／`save_settings`（`ml/local/llm.json`，git 忽略、posix 權限 600）：`{primer, questions, providers: {gemini: {enabled, endpoint, apiKey, model, conversationLimit}, claude: {…}}}`；舊的單一供應商格式（最上層 `endpoint`／`apiKey`／`model`／`conversationLimit`）讀入時變成 Gemini 那一組。`first_message`（前情提要＋資料＋問題；追問只送問題）／`export_markdown(items, conversations)`（每家的問答，不含資料）。頁面 `analysis_page`（`ui.py`，id `analysis`，不在管理分組）：供應商分頁（`ai_provider_tab`：金鑰狀態、啟用勾選〔改了立刻存〕、模型、字數上限、載入模型清單）、前情提要與常用問題、要分析的內容（估值模型＋對戰紀錄、訓練資料，對話開始後鎖定）、對話（**每家各自一條歷史** `ai-histories[名稱]`，結果分頁並排；送出給「啟用且讀到金鑰」的所有家，`ai_process_pending` 用一家一個執行緒同時送、先處理再畫元件；某家失敗只在它的分頁顯示錯誤並可「再送給這一家」，全部失敗時問題放回輸入框；某家超過自己的字數上限就略過；某家還沒有歷史就收到第一則訊息〔含前情提要與資料〕）。測試 `tests/test_llm.py`（假 HTTP）與 `tests/test_ui.py` 的 `test_ai_analysis_*`（`_ai_setup` 用暫存的 `llm.json`、測試前要 `delenv` 兩個金鑰變數）。待辦見 `docs/TODO.md` 11。
- `ui.py`：ML UI（Streamlit，`streamlit run ml/ui.py`；左側導覽（Dashboard 樣式）：「流程」分組只有「建立排程」（程式裡叫 pipeline／`pl_`，預設頁），「管理」分組「訓練資料」「估值模型」「AI 分析」「排程佇列」，「單項工作（舊版）」分組「模擬對局採樣」「模型訓練/蒸餾」「對戰驗證」（打算之後退場，見 `docs/TODO.md`），然後「說明」分組「hash 說明」「版本控管」，列在 `ui.py` 的 `pages()`（名稱是 `t("page.<id>")`），一次只畫目前那一頁；目前頁記在 `session_state["page"]` 與網址 `?page=`（重新整理不跳頁）；導覽最下方是 `sidebar_status`（只顯示正在跑的工作，排隊數用小字）。）。版面：每區一張卡片 `card(key, title, sub=None)`（`st.container(border=True, key="card-…")`，樣式在 `CSS`；卡片標題下的一句說明用 `sub` 傳入，會和標題同一行，太長時在標題右邊折行，不要另外用 `st.caption`）；所有開始鈕用 `action_row`（藍色可按、鎖住時右邊紅字寫原因、有工作在跑時寫排第幾個）；刪除用 `delete_button`（確認後才刪，排隊或執行中的工作要用的檔案不能刪）；參數格 `param_inputs` 在 `st.container(key="params")` 裡，標題統一兩行高；參數說明表（`pdoc.*` 鍵；加訓練參數時一起補）。主題色在根目錄 `.streamlit/config.toml`（與 Dashboard 同色票）。啟動檔 `start-ui.sh`／`start-ui.cmd`（綁 localhost:8501、隱藏 Deploy 鈕）。路徑一律顯示成相對專案根目錄（`rel`／`scrub`，與 Dashboard 相同規則）。
- 工作種類（`job_runner.py`）：`train_lgbm`／`train_mlp`（取消＝結束程序）、`dump`、`match`（呼叫發佈版 Runner `dotnet publish/runner/Runner.dll`，`PR_RUNNER_DIR` 可改；原始碼較新會先自動發佈；從輸出解析 `n/total games` 當進度；取消送 SIGINT，Windows 直接結束；`match` 完成後 `modelmeta.add_match`）。UI 寫的東西一律進本機工作區 `ml/local/`（被 git 忽略）：訓練的模型 `ml/local/models/`、自訂組合與自我對戰設定 `ml/local/data-configs/`（同名已存在就拒絕，內建的 `ml/data-configs/` 也算）、對戰設定 `ml/local/matches/`；模型名稱在正式與本機之間不能重複（`model_path` 用檔名找）。「模型」頁可以「重新命名」（只限本機模型：`modelmeta.rename_model` 一起改三個檔與 `.meta.json` 裡的名稱，也把本機紀錄裡指向它的舊名字改掉＝其他本機模型 `.meta.json` 的 `matches[].others[].valueModel`、`data[].valueModels` 與 `ml/local/match-records/`；正式模型追蹤中的 `.meta.json` 不改；`ml/local` 的設定檔在對話框勾選才改（`configs=`），內建 `ml/data-configs/` 與資料檔 `.bin.json` 記的路徑一律不改（`model_references` 列出三類）；排隊或執行中的工作要用它時不能改；`model_name_users` 列出還用舊名字指向它的資料與設定檔並警告）、「設為正式模型」（本機→`ml/models/`，之後 commit 並更新 `docs/models.md`）或「移到本機」（`ml/models/` 裡 git 沒追蹤的）。「自訂組合」的策略清單讀 `ml/engine-info.json`（`common.all_strategies`，排除需要 profile 的 `rule-based`），新增策略不用改 UI；說明文字是 i18n 的 `strategy.<名稱>`（`strategy_text`／`strategy_label`；沒有的就只顯示名稱）。

## 常見修改

- **管線頁加欄位**：加進項目 dict 的欄位（彈出卡的表單函式放元件、計畫函式讀欄位並算問題與詳細資料、`pl_steps` 用到才帶進工作）；文字進兩個 i18n 檔（`pl.*`、詳細資料標籤 `pl.det.*`）；舊範本缺這個欄位時計畫函式要有預設值；測試在 `tests/test_ui.py` 的管線區（`no_spawn` 讓工作只建立不啟動、`inline` 讓彈出卡畫在頁面上，測完刪掉寫進 `ml/local/` 的檔案）。

## 雷

- Streamlit 頂部工具列是固定 60px、浮在內容上方的透明條（右邊選單、側邊欄收起時左邊有重新展開鈕）。頁面標題（`st.title`）放在這條裡：`.block-container` 的 padding-top 是 0，標題元件高度 `--bar-h`（60px）並垂直置中，所以標題和選單同一水平線、上面沒有多餘留白；內容左邊的 padding（約 5rem）讓標題不會被重新展開鈕蓋住。不要再加 padding-top，也不要在標題前放會佔高度的元件（CSS 的 `<style>` 區塊所在的元素容器已用 `:has` 隱藏，否則它的 1rem 間距會把標題推下去）；升版後若工具列高度變了，改 `--bar-h`，並用截圖確認標題中心與選單對齊。表格（dataframe）不能放按鈕：要逐列操作就用勾選＋一個按鈕（`delete_button`），或用 `st.columns` 自己畫列（`queue_page`）。
- 深色主題的輸入框底色（`secondaryBackgroundColor`）和卡片同色、又沒有框線，輸入框會整個看不見：`CSS` 裡另外把輸入框、下拉選單、數字框、單選群組（`stRadioGroup`）、指標（`stMetric`）改成較深的底色＋`#333a4b` 框線（聚焦時藍框）。Streamlit 1.6x 起文字框與下拉選單改用 react-aria（`data-testid="stTextInputRootElement"`、`.react-aria-ComboBox`），沒有 `data-baseweb` 了；舊版仍是 baseweb：選擇器兩種都要列（只寫 baseweb 時文字框、下拉選單沒框，數字框卻有）。新增元件種類或升版後用截圖確認。
- 刪除鈕：`delete_button` 用 `st.dialog` 確認（`confirm_delete`），不要用 popover：popover 在刪除後的 rerun 仍保持開著。按鈕包在 `st.container(key="del-…")` 裡，CSS 用 `st-key-del-` 讓它紅底靠右；確認鈕 key `<key>-confirm` 也是紅色，取消鈕用 `keep-` 開頭避開紅色。刪除後 `del-gen` 加一，有勾選的表格把它放進 key（`dumps-<n>`、`cfg-table-<n>`）：否則舊的勾選（列號）會指到別的檔案。新的刪除鈕 key 也要以 `del-` 開頭。
- 表格一律用 `grid()`（包 `st.dataframe`）：它多留 18 px 給水平捲軸，否則 Windows 的捲軸會蓋住最後一列；最多顯示 10 列再捲動。
- 同名檔案的檢查看配方，不只看檔名（`same_name_notice`）：配方相同→「完全相同，不需要覆寫」，不同→列出差異；被模型用過的資料覆寫時列出模型；不同名但配方相同→提示重複。覆寫（資料、模型、對戰結果）也會被「排隊中或執行中的工作要讀它」擋下（`reader_problem`，與刪除同一套規則；`job_reads` 列出工作會讀的檔案：訓練資料、對戰的模型、設定檔裡的估值模型）。工作的 spec 與 `rel(out)` 的路徑寫法要一致（`rel()` 產生）。
- 下拉選單與表格的「檔案」欄只顯示檔名（選項的值仍是相對路徑），路徑改用小字寫在下面並附「開啟資料夾」（`folder_line(路徑, key)`，key 以 `folderline-` 開頭，CSS 讓它一行、小字、連結樣式）；新增檔案清單照做。
- 設定檔的 `output.dumpRate`（選用，C# `OutputConfig.DumpRate`）是 dump 抽樣率的預設值：Runner 的 `--dump-rate` 優先，其次設定檔，最後 0.02；ML UI 選設定檔時帶入它，沒寫才猜（有 MCTS 座位 0.05，否則 0.01）。
- 設定檔模式的局數、種子、抽樣率輸入框的 key 含設定檔名稱，換設定檔才會重新帶入預設值（以前 key 只有模式，換設定檔後種子停在上一個）。
- 「管理」分組：**刪除、重新命名、設為正式／移到本機只在管理頁**（訓練資料頁、模型頁），其他頁只讀；兩頁都是「清單＋勾選列＋下方詳細資料」同一頁（以前模型清單與詳細資料分兩頁），舊網址 `?page=modellist` 由 `current_page` 轉到 `models`。
  - 「估值模型」頁（`models_page`，id `models`）：上卡 `models_list`（快篩 `st.pills`：位置 git／local、種類、人數、規則版本；每組各自一個框 `st.container(key="filterbar-mf-<名稱>")`，CSS 是圓角晶片，選中的填藍色；不選＝全部；沒有 `.meta.json` 的模型在選了規則版本時不顯示；數字欄 `TextColumn(alignment="center")` 置中；表格可多選，表格 key 含快篩值與 `del-gen`），勾選後下方**操作列**（`st.container(key="actionbar-models")`，CSS 上緣線；左邊安全操作、右邊危險操作）放：重新命名｜設為正式／移到本機（`move_buttons(path, c_rename, c_move)`，剛好勾一個才可按，否則停用；成功後 `del-gen` 加一清掉勾選）｜複製詳細資訊（n）（`digest_box(text, key, n, container)`：藍色主按鈕，沒勾或太長時停用〔`digest-off-*` 淡藍〕，回傳字數提示放在操作列的提示欄）｜「刪除勾選」（`del-models`，操作列最右、深底紅字；對話框裡的確認鈕仍是實心紅）一併刪模型檔、`.meta.json`、`.check.txt` 與 `ml/local/match-records/` 的對戰紀錄，排隊或執行中的工作用到的模型不能刪，刪正式模型要另外 commit 並更新 `docs/models.md`；下卡依勾選數：0 提示、1 個 `model_detail`、2～4 個 `compare`、更多提示最多 4 個。`model_detail` 依序是小卡（`version_tiles(…, centre=True)`）、對戰結果、訓練資料（`model_data_table`：欄位與順序和訓練頁選資料的表格相同；人數、特徵版本取模型的，大小與引擎 commit 只在磁碟上的 dump 還是同一個 hash 時才有，否則「—」）、訓練參數與驗證、曲線（`loss_chart`：altair，不可縮放，不要用 `st.line_chart`）與特徵重要度。`compare` 用 `version_table(..., css="cmp")`，結果列標出最好的模型（`td.best`）。對戰紀錄表（`match_columns()`）的「紀錄存放」＝git 或 local。

- Streamlit 的元件 ID 由種類＋參數產生：不同頁面裡標籤相同的按鈕（例如三個「加入排隊」）會撞 ID 而報錯，要給 `key`。
- Streamlit 的下拉選單不會更新已顯示選項的文字：選項標籤不要放會變的狀態（`queue_page` 的「工作詳細」下拉選單只放名稱與時間）。表格裡數值欄的缺值會顯示灰色 None：要顯示「—」就先轉成文字（`models_table`）。
- **其他頁跳到「建立排程」並放好一個項目**：`common.open_in_pipeline(kind, item, players, note)` 把項目放進 `session_state["pl-prefill"]` 並 `go("pipeline")`；排程頁一開頭（`pl_restore` 之後、畫人數單選鈕之前）由 `pl_take_prefill` 接手：人數不同就換人數並清空表單，再加進清單、toast 顯示 `note`。項目用 `common.match_item`（對原版 MCTS，對戰驗證頁的預設值）、`common.train_item`（既有資料、預設參數、時間戳名稱）產生。目前的入口：估值模型頁操作列「對戰這個模型」（`md-to-match`，剛好勾一個有 `.meta.json` 的模型）、訓練資料頁操作列「用這些資料訓練」（`dm-to-train`，勾選的資料人數與特徵版本都相同）。頁面模組不 import 別的頁面，所以一律走這個 session 交接，不要直接呼叫 `pipeline.py` 的函式。
- 「建立排程」頁的開始卡：排程名稱可以留空（下方小字寫會用的預設名稱），只有一個工作時開始鈕寫「開始」，多個時「加入排程」。名稱框的標籤固定不變（標籤跟著內容變會讓 Streamlit 忘記打的字）。
