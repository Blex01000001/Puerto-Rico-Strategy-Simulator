# 局面估值模型：研發紀錄與目前狀況

MCTS 用的學習型局面估值模型（`valueModel`）的總表：每個模型是什麼、怎麼來的、多強、現在用不用。細節與實驗過程在 `docs/strategy-analysis.md` 第 10 節，流程在 `ml/README.md`。
**只記目前狀態**；勝率一律來自模型 `.meta.json` 的對戰紀錄（`python3 ml/model_report.py` 會印出最新數字），不要憑記憶填。

## 目前結論（4 人局為主）
- **日常使用：`4p-v2.txt`**（LightGBM）。對原版 MCTS 同模擬次數 68.1%、約同時間 65.0%；對手寫桌 94.6%（原版 MCTS 84.9%）。
- 4 人局已到頂：第二輪自我對戰的 v3 和 v2 同桌對打 49.0% 對 49.4%。要再進步需換方向（待辦 6：更多模擬、新特徵、較高品質的自我對戰資料），不是多迭代。
- 本機實驗（分析文件 10.4，模型不在 git）：手寫資料多打 10 倍局數沒有幫助；同樣資料加大模型（800 樹、127 葉）同模擬次數同桌 53.9% 對 44.8%（剛好顯著），約同時間（150 次對 300 次）50.4% 對 47.0%＝打平；高品質自我對戰（300 次、2 萬局）的 `4p-v4-hq` 對原版 69.4%、對手寫 90.7%，與 v3 在誤差內（分析文件 10.5）。
- MLP 和 LightGBM 同資料一樣強，但推論較慢；目前以 LightGBM 為主。
- 3 人局擱置中（使用者指示）：最好的是 `3p-v3.txt`，對原版贏、對手寫桌仍不如原版 MCTS。

## 怎麼讀這張表
- **對原版（同模擬次數）**：模型版 MCTS 300 次對原版 MCTS 300 次，同桌另有手寫策略（4 人局 cheap-engine、build-first；3 人局 cheap-engine），balanced 240 局，種子 9191。4 人局平均水準是 25%。
- **對原版（約同時間）**：模型版只給 180 次（LightGBM 推論的成本約讓 300 次的時間只夠 180 次），看值不值得。
- **對手寫桌**：4 人局 corn-shipper、corn-to-premium、build-first（與分析文件第 5 節同桌，408 局，種子 5151，原版 MCTS 84.9%）；3 人局 corn-shipper、build-first（240 局，種子 5252，原版 MCTS 67.5%）。
- 勝率後面是 95% 信賴區間；差距小於它就當作一樣強。
- **資料**：手寫＝`4p-hand-a/b/c`（三種手寫策略混桌，各 2 萬局）；隨機＝`4p-random`；自我對戰 n＝用前一代模型的 MCTS 互打產生（`ml/data-configs/4p-selfplay-v*.json`）。

## 本機模型（使用者自己訓練的）
ML UI 訓練的模型預設放在本機工作區 `ml/local/models/`（被 git 忽略），不列在這裡。驗證後覺得值得保留的，在 ML UI「模型清單」按「設為正式模型」搬到 `ml/models/`，再 commit，並在上面的表格補一列。

## 新增一個模型時（使用者或 Claude）
1. 訓練並跑對戰驗證（至少「同模擬次數」與「約同時間」兩場；要和舊數字比，用上面同樣的桌子與種子）。
2. 正式模型：模型、`.meta.json`、`.check.txt` 三個檔一起放進 `ml/models/`（ML UI 的「設為正式模型」會一起搬）。
3. `python3 ml/model_report.py --players 4` 取得數字，在對應表格加一列；狀態寫「使用中／保留／對照組」，備註寫它和前一代差在哪（資料、參數或特徵）。
4. 結論有變（例如新的最強模型），同步「目前結論」、`docs/strategy-analysis.md` 第 10 節與 README。
5. 刪除模型時把狀態改成「已刪除」並保留這一列（數字留著，檔案可從 git 歷史取回）。
6. 改了特徵清單（`ValueFeatures.cs` 的 `Version`）時，舊模型會全部無法載入：在表格加一欄或分一張新表，註明特徵版本。
